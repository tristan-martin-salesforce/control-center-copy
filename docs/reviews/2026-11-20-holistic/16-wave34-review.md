## Findings

Severity: **H** (fix before the branch is pushed) · **M** (fix in the release pass if cheap, else first 2.0.x) · **L** (later).

**W34-1 (M) · The worker can be left under the old label, and missing after a reboot.** `scripts/ops/lib/migrate-state.mjs:160` captures `wasLoaded` the moment the detached migration starts, and `finish()` (:261-266) starts only those kinds under the new labels. In the 1.x flow the migration is spawned by the **web** agent's `run-service` (first bootstrap of the old updater's restart loop, `0a62c19:scripts/ops/lib/update.mjs:116-119`), while the **worker** bootstrap comes next: if `launchctl print` runs before the worker is loaded, `wasLoaded = ['web']`, `com.commandcenter.worker` is never started, the old worker plist is deleted, and the old-label worker keeps restarting under launchd with an env-file path that no longer exists (`run-service` reads an empty env, waits for a bundled socket that does not exist, exits 0, repeats every ThrottleInterval) until logout, after which there is no worker at all. `tests/ops/migrate-state-service.test.ts:48` pre-loads both labels, so the race is not covered. Fix: in `finish()` bootstrap **every** kind whose new plist was written (web and worker unconditionally; db when its plist exists), independent of `wasLoaded`; and in `run-service.mjs`, when `--env-file` is under the old folder and the migration is no longer needed, exit 0 without the Postgres wait (an orphan old label). Add the race to the service test (worker loaded after the first `launchctl print`). Owner: `p4-release-2.0`.

**W34-2 (M) · Five CHANGELOG 2.0.0 lines are not true in code.** (a) "The sidebar has seven items": `src/components/shell/nav.ts` has 5 + 6 items in two groups plus Settings and Health (13 hrefs, unchanged since `b80d2af`); D-86 decided seven (`docs/decisions/0086-needs-you-queue-and-nav.md:14`). (b) "Settings has five sections": six groups (Me, Sources, Sending, Budgets, Data, Advanced; `src/components/settings/derive.ts:180-236`). (c) "scans default to fetch-then-interpret (Settings ▸ Engines)": the mode is `CC_SCAN_MODE` (`src/scanner/runtime/mode.ts:13-15`), there is no Settings control and no "Engines" section. (d) "Settings ▸ Assistant ▸ Routing: Auto": routing lives in Budgets (`RoutingAndRankingSection`, `SettingsPage.tsx:214`), the closing engine in Sending (`ClosingEngineSection`, :205). (e) "Needs you ... ten providers": nine provider files, eleven kinds (`src/engines/needs/providers`). Fix the wording (CHANGELOG is the one document a teammate reads before updating); for (a) also decide: amend D-86 to the two-group sidebar as built, or cut the Context group in 2.0.x. Owner: `p4-release-2.0` (wording), `post-2.0` (D-86).
