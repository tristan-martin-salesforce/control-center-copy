## Remaining

6 baselined nodes (was 22), one rule (label-content-name-mismatch), all on History: the 3 calendar days per theme,
accepted (below). Home and the palette, cheat sheet and Assistant dock states over it are 0 in both themes, so the Do
now draft buttons are fixed and their baseline entries are gone. `tests/a11y/baseline.json` now lists only
`dark /history` and `light /history`, so a new violation anywhere still fails `npm run test:a11y`.

- **Full rescan (`post-a11y-rescan`, 2026-11-21)**: production build, `CC_DATA=mock`, port 4440,
  `npm run test:a11y -- --port 4440`: `a11y: 122 scans, 6 violating nodes, 0 new`, no skip and no timeout, 666 s.
  The baseline was rewritten to exactly what `--update` writes from that run (down from 22 to 6; nothing went up).
- **The stall, and the scanner fix** (`tests/a11y/axe-pages.ts`). The old run shared one browser context per theme,
  closed it unbounded between the passes, left Playwright's action timeout at its default of none (a `click` or
  `hover` under an overlay waits forever) and bounded no scan as a whole, so any hang stopped the run with Chromium
  idle. Now: a fresh context per scan (no storage, open overlay, focus or live poll carries from one target, state or
  theme into the next, which is also the state reset between themes); a 20 s action default; each scan bounded
  (`--scan-timeout`, default 150 s) and turned into a `tout … timed out: <target> <theme>` row while the run goes on;
  page, context and browser closes bounded at 10 s; a per-scan line with the elapsed time and a closing `done in Ns`.
  With these the full run finished first time; which of the hangs it was is not pinned (the old shape was not rerun
  to reproduce it in the time).
- **Slow, not stalled**: `/work/:id`, `/agents`, `/initiatives/:id` and `state:review-prompt` (over `/agents`) each
  take about 45 s per theme, which is `settle`'s own cap: their text or requests never sit still for 1.5 s (a live
  poll or ticking figure). They are scanned once the cap passes; finding what keeps them moving would cut about
  6 minutes off the run.
- **Fixed (`post-a11y-leftover`): Getting started card** (`src/guide/GettingStarted.tsx`, every page, 110 nodes). No
  aria-label any more: the title is read as shown, the short "1/5" (or "Done") is `aria-hidden` and a visually hidden
  ": 1 of 5 done. Next: …" stands in for it, so the name is still "Getting started: 1 of 5 done. Next: Check your role
  and thresholds". The collapsed rail icon is unchanged (its badge figure is in its name). Test:
  `src/guide/__tests__/getting-started.dom.test.ts`.
- **Fixed (`post-a11y-last`): Today meeting blocks** (`button[data-event-id]` in `DayTimeline.tsx`, 4 per theme). Why
  they differed: the aria-label was "time · title · badge" while the block shows "★ title", the badge or the meta line
  ("now · 12m left", "Declined", "15:00–16:00 · prep: 20m"), so the star, the live countdown and the prep note were
  shown but not named. Fixed on the smaller side: no aria-label on a block that shows text, the star is `aria-hidden`,
  and a visually hidden suffix (`eventSpokenSuffix`) adds only what the block leaves out (the time when the meta line
  doesn't carry it; the declined line when a badge takes its place). A tiny block shows nothing and keeps the full
  aria-label. axe on the production mock build: `/today` 0 in both themes. Test: `meeting-prep-note.dom.test.ts`.
- **Fixed (`post-a11y-last`): Home "Do now" draft buttons** (`button[data-draft-id]` in `DoNow.tsx`, 2 per theme on
  `/` and the palette, cheat sheet and Assistant dock states over Home). The name was "Open draft 1 of 3: who, text"
  and left out the shown age. Now it is the shown who, line and age, then a visually hidden " · draft 1 of 3, opens
  it"; "+N more" reads "+N more to approve · opens draft 4 of 6". Test: `briefing-polish.dom.test.ts`. Confirmed 0
  by the full rescan; their baseline entries are gone.
- **History calendar days** (`button[data-history-day]`, 3 per theme, kept in the baseline on purpose): named by the
  date and its hours ("Wednesday 18 November: 6 h…") while the cell shows only the figures. A calendar grid's day is
  conventionally named by its date (WAI-ARIA date-grid pattern; a screen reader user moving through the month needs
  the date first, and the figure alone would read "6 h" with no day), so this mismatch is accepted, not a defect.
