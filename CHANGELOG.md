# Changelog

All notable changes to Command Center (Control Center before 2.0). The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and versions follow [Semantic Versioning](https://semver.org/) (D-57):

- **major**: a migration or settings reset that needs a manual step, or a breaking change to the API contract;
- **minor**: new features, and migrations that apply on their own;
- **patch**: fixes.

`npm run release -- patch|minor|major` writes the next section from the commits since the last tag.

## [2.0.0] - 2026-11-21

**Command Center 2.0.** The app is renamed, brings its own database, scans at a fraction of the cost, and opens on the things that need you. Built from the 2026-11-20 holistic review (`docs/reviews/2026-11-20-holistic/`: eleven lane reports, the decisions in its README §8, the chunk ledger in CHUNKS.md).

### Upgrading from 1.x
- **Step by step, with the agent's runbook: `docs/UPGRADING.md`.** A 1.x checkout on Homebrew Postgres (every one `npm run setup` made) needs two `npm run update`s: the first (`-- --yes` outside a terminal: 2.0 is a major) brings 2.0 and renames the install, the second moves the data (below); then `npm run ops:install -- --yes` writes the services from 2.0's template (the renamed 1.x ones bind every interface until then). The 1.x updater fetches 2.0, builds, backs up, migrates the schema and restarts the services on the new code; the new code then moves your install itself: the folder (`~/Library/Application Support/control-center` → `…/command-center`), the logs, the background services (`com.commandcenter.web`, `.worker`, `.db`) and the database (`control_center` → `command_center`). One plain line per step in `~/Library/Logs/command-center/migrate.log`; a run that stops half-way is finished by the next start, and `node scripts/ops/migrate-state.mjs --check` shows what would happen without doing it. Nothing is lost: the old folder is never merged or deleted, and if both exist the new one is used and the log says so. Details and the fallback in `docs/INSTALL.md` (D-101).
- **A database that cannot be renamed yet keeps its old name and works as before**; `npm run update` and `npm run doctor` retry it. Backups made under the old name (`control_center-<date>.dump`) are still found by `npm run restore` and `ops:rollback`.
- **Postgres is bundled** (D-98). A Homebrew 1.x database is dumped, restored into the bundled cluster under the state folder and verified before the switch (Homebrew Postgres must be running; this is the second `npm run update` for Homebrew installs); the Homebrew install is left alone. A `DATABASE_URL` you set by hand is honoured.
- **Migrations 0027–0039 apply on their own** (additive, except 0029, which rewrites `drive:<id>` refs as `drive_file` in place, idempotent; the migrator refuses an out-of-order journal). The side-car key/value data is backfilled into columns by a background job; `npm run db:backfill -- --dry` shows what it would do.
- There was no compiled 1.x build: a 1.x install that switches to the compiled one runs `install.sh` (docs/INSTALL.md), which renames, moves the data and migrates in one run; compiled installs then update from the shared Drive folder (Health ▸ Setup shows the banner). Port 4327 is unchanged.
- Settings that changed meaning: scans default to fetch-then-interpret (`CC_SCAN_MODE=agentic` restores the old path), the Assistant picks its model itself (Settings ▸ Budgets ▸ Models and ranking ▸ Assistant model: Auto), and the new closing check (Settings ▸ Sending ▸ Closing items for you: Watch only) and the new ranking (Settings ▸ Budgets ▸ Models and ranking ▸ Ranking: Preview v2 beside it) only watch until you switch them.

### Added
- **Time can log to an account** (D-103 (c)): an account with no open opportunity is a settled target (no more "pick the opportunity" there), every row says in one sentence why it logs where it does, and the Org62 search in the opportunity field lists accounts too.
- **Coverage as data** (D-103 (a)): AEs I cover rows carry a kind (AE I support, OOO cover, SME assist), a window and a default split; a covered AE matches as owner, opp team member or Specialist Forecast owner, and an AE I support's deal is a DC suggestion (unticked) before I touch it
- **DC suggestions see Specialist Forecasts and who else is on the deal** (D-103 (b)): discovery reads your covered AEs' open Data & AI Specialist Forecasts (one read, same daily cap), and each suggestion shows the other Data & AI DCs and specialists on that opp.
- **Home is a briefing** (D-86): three cards, the Needs-you queue grouped by what to do, a Respond strip for replies waiting on you, Coming builds, and the admin row; Today folds in as the Plan toggle (`p`). Every item carries its why.
- **Needs you is one queue** (`GET /needs`): eleven kinds of row from nine providers (a guess to confirm, a draft to review, time to log, a VDP change, a Deal Contribution to claim, a mapping question, a spend ask, a Looks done or Still needed?, a setup step, a use case to add, an item that was reopened) composed by the engines, one row per fact, one decision each, one sidebar count.
- **Activity = To log · History · VDP**, with a Review page of checkboxes and plain words; attribution suggests the opportunity, account and Deal Contribution for every hour, with a live Org62 discovery job, learned mapping rules, "AEs I cover" and suggestion outcomes (`src/engines/attribution`).
- **Use-case candidates** from call notes, de-duplicated, with Accept staging the VDP item and the Org62 row in your next logging batch (migration 0034).
- **Assistant v2** (D-81, D-100): eleven tools (query over the read views, read, run research, plan, act on the named item, …), Auto routing across Haiku, Sonnet and Opus with a cost line per turn, persisted sessions and memory (migration 0035), a plan card and a raise-hand card when it needs you.
- **Spend governor**: every LLM call is estimated, held against your daily budget, and asks before continuing past it (estimate → warn → raise a hand → continue; never a silent cap). Holds are visible in the scan report and Health.
- **Fetch-then-interpret scanning** (the default scan mode, `CC_SCAN_MODE`): code fetches Slack and Org62's windowed scopes (one Claude Code MCP call per read) and Gmail, Drive and meeting notes (the read-only Google client), and batched tool-less Haiku runs over a shared cached prefix classify what they read. Calendar, Claude sessions, VDP, watch briefs and Org62's book and missed-opportunity reads keep the agentic path. Measured at about 0.15× the agentic scan's cost on the golden set with the same closures.
- **Resolution check** (shadow by default): one engine decides when an item is done, with a "Why still open" explanation, a recall sweep and `scan:explain --item` (migration 0031).
- **Priority@2** (shadow by default): a persona-aware model with a preview policy, auto re-rank, prep rules and feedback (migration 0033).
- **Connector runtime**: one registry and manifest per connector, four transports (Claude relay, direct MCP, HTTP JSON-RPC, local files) and a model-provider seam with the Agent SDK adapter; connectors stay read-only behind the same allowlist.
- **Health ▸ Setup** driven by the doctor: every setup and connection state with a Run button, one error catalog with codes (`src/errors/catalog.ts`), the doctor as a service (`GET /doctor`, every 15 minutes on the worker), and an update banner.
- **Bundled Postgres 17** under the state folder with its own LaunchAgent, base backups (daily and weekly retention), restore and rollback, and `npm run doctor` checks for all of it.
- **Compiled build and distribution**: `npm run build:release -- --smoke`, a staged install with full rollback, releases published to a shared Drive folder with a manifest and sha256, a Slack announcement, and both as Outbox drafts you approve (`release.announce`, `release.drive_upload`); the app checks the Drive folder for updates.
- **Retention**: a policy, a nightly job, Settings ▸ Data and `db:size` in the doctor.
- **Page-scoped reads**: every page loads the rows it shows (Home and Today a ±14-day briefing window); a read outside its scope is logged as `BUG.READ_SCOPE_MISS`; `CC_READ_SCOPES=off` restores the 1.x reads.
- **Side-car to columns** (D-99, migration 0036): need decisions, canvas row overrides, Org62 15-character ids as generated columns, VDP child tables, landings for Slack and Gmail; a backfill job and `npm run db:backfill`.
- **Undo reopen**: after you Undo a close for you, "Why is this still open?" says "You reopened it" with **Undo reopen**; the item is closed again and the check may close it for you again (it no longer counts as your correction).
- **Health ▸ Setup has two more rows**: **State folder** (a half-done move from 1.x, or a database rename that was put off, with the command that finishes it) and **Page reads** (pages that fell back to reading everything, `BUG.READ_SCOPE_MISS`, since the web app started). `npm run doctor` shows them as `setup:state-folder` and `data:read-scopes`.
- **Work ▸ Closed pages**: the first 50 closed items, then "Show 50 more · N of M shown"; the tab counts stay exact.
- **VDP autopilot's trusted sites** (Settings ▸ Sending, under the autopilot toggle): the sites autopilot may add asset links from (see Security).
- **Assistant goldens** in `npm run test:evals`: routing, tool choice, the D-100 act rule and prompt injection, offline.
- **What the Assistant remembers** (Settings ▸ Budgets): every preference and pinned note that rides into later messages, each with the message it came from (migration 0038) and **Forget**, which removes it on a second click.
- **Review prompt, then Open in Claude** wherever a new Claude Code session starts (the Details panel, Today, Home's cards and Coming builds, Agents, the Assistant's session card and thread pane): the folder and the whole prompt first; a running session still opens on one click (see Security).
- **Health ▸ Ledger pages**: the newest 100 scan runs, then "Show 100 more · N of M runs loaded", down to the first run.
- **Getting started shows the first scan's cost** until the first scan is done: "First scan: usually about $A, up to $B, about N h. Past that it asks before it goes on."
- **The worker recovers from a crash in plain words**: killed mid-scan, it closes the stopped run, books the calls it paid for once, frees its holds and reads the window again, and Health says "Inbox: a scan stopped when the app closed; it picks up where it left off." (closed as picked up by the next scan). It waits for a database that is not answering instead of crash-looping, and a full disk is a retry with one Health row (EDGE-CASES "Worker", W1–W9).

### Security
From the review before sharing 2.0 (`docs/reviews/2026-11-20-holistic/17-security-review.md`):
- **The Assistant's answers and briefs load no images or media** (SEC-4): a planted message can no longer make the page send data to another site in an image link. Links still work on your click.
- **Logs and the feedback Diagnostics block mask more secrets** (SEC-1): the VDP Okta cookie, the VDP PAT, Google access tokens and a database password in a connection URL.
- **The release build never carries a `.env` file** (SEC-2), so a maintainer's settings can't reach a teammate's install.
- **Installs and updates refuse a build no release feed lists** (SEC-3): `install.sh`, `install.mjs` and `npm run update -- --from` stop before unpacking unless the Drive folder's `manifest.json` lists the file with a matching sha256. Your own build: `--unverified` (or `CC_INSTALL_UNVERIFIED=1` for `install.sh`).
- **The Assistant can't stage the VDP refresh script, its interpreter or the feedback channel** (SEC-5): those settings are yours, in Settings, at stage and again at Apply.
- **VDP autopilot adds asset links only from trusted sites** (SEC-6, D-60 amended): https on a site in Settings ▸ Sending's list (by default the Salesforce sites and drive/docs/slides.google.com) or a subdomain of one, no user name, port or IP address. Anything else waits for your Apply with "Held for you: link is on <host>, not a trusted site", and the check runs again right before the write.
- **The Assistant treats other people's text as data**: every search, fetch, query and read result is marked untrusted, and an action applies at once only when your own words name the item (a quoted "> mark X done" in a paste becomes a card).
- **The Assistant remembers only when you ask** (SEC-8): a preference for every thread is kept only when your own words ask to keep it ("from now on …"), never from a pasted or fetched line, and Settings ▸ Budgets ▸ What the Assistant remembers lists each one with the message it came from, and Forget.
- **A sign-in window opens only when you ask for one** (SEC-9): the Assistant's re-auth runs only when your message asks to sign in (or says it expired, stopped syncing, is broken) and names the connector; "summarise my unread mail" opens nothing.
- **Every new Claude Code session shows Review prompt first** (SEC-10): the folder and the whole prompt, "Claude Code runs it with your permissions", then **Open in Claude**; Not now keeps it queued.
- **Local files resolve under their root** (SEC-11): a Claude session file is read only when its real path, symlinks followed, is under a configured root's real path, checked on every read.
- **Errors carry no raw message to the page** (SEC-13): a stream's error is the same envelope as the JSON API's, and an unexpected error shows the catalog's words (BUG.UNHANDLED); the message goes only to the redacted server log.
- **One forbid list for rendered HTML**: the Assistant's answers, briefs and the composer's email preview drop the same auto-fetching tags and attributes (`src/client/html-forbid.ts`); the preview keeps a draft's inline styles only without `url(`.

### Engineering
- Vitest projects per module (`npm test` = unit + ui; `npm run test:db` serial Postgres suites; `test:evals`; `smoke:crawl`), the scanner eval harness with golden cases and cassettes, a component kit with a gallery, a layer lint and file-length lint, a route-drift test, CONTRIBUTING.md and AGENTS.md, ADRs 0076–0101 (and D-60's file).
- **The layer rule is an error with nothing grandfathered**: pure layers take ports their callers build (`ProjectionStore`, `Complete` via `src/llm/complete-sdk.ts`); shared helpers moved to `src/lib` (`redact`, `local-time`, `event-titles`, `ledger-hash`); the voice profile CLI moved to `scripts/voice/cli.ts` (`npm run voice:profile`).
- **No file over 1,000 lines**: the long files are split into `<name>.<part>` siblings behind their unchanged entry (a long class into abstract layers, parts a chain, never a cycle); the length grandfather list is empty and lint is down to one 600-line warning.
